# 엑셀 통합 문서 기본 글꼴(Calibri) 후처리 검토

> 2026-10-26 검토 — **결론: 보류.** 값이 있는 칸은 이미 맑은 고딕이고, 고치면 인쇄 배율·페이지 나눔을 다시 맞춰야 해서 얻는 것보다 위험이 크다. 고객이 요청하면 별도 PR로 진행한다.

## 지금 상태

- exceljs 가 저장한 `xl/styles.xml` 의 첫 글꼴(= 기본 셀 스타일 "Normal"이 쓰는 글꼴)은 `Calibri 11` (한글 charset 없음)
- 원본 양식 `ledger/export/ledger-template.xlsx` 의 첫 글꼴은 `맑은 고딕 11` (charset 129)
- 값이 있는 칸·사용 열은 모두 맑은 고딕을 직접 지정해 두어서, 차이는 **서식 없는 빈 칸**과 엑셀이 계산하는 **기본 열 너비·행 높이**에만 있다

## 방법 (다시 할 때)

저장한 파일(zip)에서 `xl/styles.xml` 의 `<fonts>` 안 **첫 `<font>` 하나만** 원본 양식의 첫 글꼴로 바꾼다.

- 값을 코드에 적지 않고 원본 파일에서 복사
- 글꼴 개수·번호는 그대로 → 다른 칸이 쓰는 글꼴 번호(fontId)는 움직이지 않음
- zip 은 exceljs 가 이미 쓰는 JSZip 으로 그 항목 하나만 교체

## 위험 4가지

1. **열 너비가 바뀐다 (가장 큼)** — 엑셀은 열 너비를 "기본 글꼴의 숫자 한 글자 폭" 단위로 계산한다. 맑은 고딕은 Calibri 보다 폭이 넓어 같은 너비 값이 더 넓게 그려진다 → 월별 리포트의 고정 배율·수동 쪽 나눔(`export/page-plan.ts`), 다른 시트의 "너비 1페이지 맞춤"이 어긋날 수 있다
2. **행 높이가 바뀐다** — 높이를 직접 지정하지 않은 행의 기본 높이가 약 15pt → 16.5pt 로 늘어 세로 쪽 나눔이 밀릴 수 있다
3. **zip 다시 묶기** — 압축 방식·항목 순서를 바꾸거나 다른 부분을 다시 쓰면 엑셀이 "복구" 창을 띄울 수 있다 (그 항목 하나만 바꾸면 낮음)
4. **문자열 치환 실패** — exceljs 버전이 바뀌어 XML 모양이 달라지면 치환이 깨질 수 있다 → 첫 `<font>` 를 못 찾으면 **바꾸지 않고 원래 파일 그대로** 내보내야 한다

## 테스트 방법

- 단위 테스트
  - 첫 글꼴 = 원본 양식의 첫 글꼴
  - `styles.xml` 을 뺀 나머지 zip 항목이 바이트 단위로 같음 (해시 비교)
  - 글꼴 개수 같음, 값 덤프(`dumpWorkbook`) 같음, 기존 결과물 스냅샷에서 글꼴 1칸만 바뀜
  - 채권·채무 왕복 테스트(다운로드 → `parseLedgerSheet`) 그대로 통과
- Mac Excel 로 6종 모두 열기
  - 복구 창이 뜨지 않는지
  - PDF 로 내보내 지금 결과와 페이지 수·쪽 나눔 위치·잘림 비교 (AppleScript PDF 저장 + PDFKit 측정 — 월별 리포트를 가장 먼저)
