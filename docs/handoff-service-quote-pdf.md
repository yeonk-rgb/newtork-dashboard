# 인계: 유상 A/S 견적서 PDF 업로드 (서비스팀 담당자용)

> 작성: 경영지원팀 담당(2026-10-25). 이 저장소는 경영지원팀 모듈 전용이라 서비스 폴더는 손대지 않았다 (CLAUDE.md "운영 규칙").
> 고객사가 "나중 단계(서비스팀 견적서 업로드)용"으로 보낸 견적서 PDF 1장을 보고 정리한 내용이다. 원본 PDF는 이 저장소에 없고, 넣지도 않는다.

## 0. 먼저 지킬 것

- **실제 견적서는 시험 데이터로 쓰지 않는다.** 받은 샘플에는 거래처명·수신자·담당자 이름과 휴대폰 번호, 회사 직인 이미지가 들어 있다. 저장소·픽스처·스크린샷·이슈 어디에도 올리지 말 것.
- 시험용 파일은 **같은 양식에 가짜 내용**으로 만든다 (2단계 엑셀 이관 때 `scripts/make-ledger-fixture.ts`로 원본 빈 양식에 "(가상)" 거래처를 채운 방식 참고). 빈 견적서 양식(실데이터 없는 원본)을 고객사에 따로 요청하면 가장 좋다.
- PDF 글자를 AI(스캔본용 Claude API)로 읽게 하면 거래처·담당자 정보가 외부로 나간다. **고객사 동의 전에는 글자 PDF만 서버에서 직접 읽는다** (경영지원 AI 분석의 05-19번과 같은 원칙).

## 1. 양식 구조 (A4 세로 1장, 문서 코드 `NTK-ADM-200-06`)

받은 샘플은 **글자를 선택할 수 있는 PDF**(스캔 아님)였다. 다만 그냥 텍스트를 뽑으면 **읽는 순서가 섞인다** — 표 칸들이 줄 단위로 뒤섞여 "합계 금액 … 원 (부가세 포함) 전화번호 … 팩스번호"처럼 다른 칸 글자가 한 줄에 붙어 나온다. → `pdfjs-dist`로 **글자 조각의 좌표(x·y)**를 받아 "라벨 칸 오른쪽에 있는 값"을 찾는 방식으로 읽을 것.

| 위치 | 항목 | 형식·예시(가짜) | 비고 |
|---|---|---|---|
| 왼쪽 위 표 | 견적 번호 | `NTK-YYMMDD-NNNN` (예: `NTK-261020-0001`) | YYMMDD = 견적 작성일로 보임. 같은 날 순번 4자리 |
| 〃 | 날짜 | `YYYY-MM-DD` | 견적일 |
| 〃 | 업체명 | 거래처 상호 | **거래처 정보** |
| 〃 | 수신자 | "○○○ 대표님" 등 | **개인 이름 — 저장 여부 검토** |
| 〃 | 합계 금액 | `1,100,000 원 (부가세 포함)` 형태 | 아래 금액 검증 대상 |
| 오른쪽 위 표 | 등록번호·상호·대표·주소·업태·종목·전화·팩스 | 뉴토크코리아 자기 정보 (고정) | 읽지 않아도 됨. 직인 이미지 있음 |
| 가운데 | 사업명 | "(지역)(시설) … 수리" 형태 | 지역 추출 후보 (3장) |
| 〃 | 비고 | 자유 글 | 비어 있을 수 있음 |
| 품목 표 (12줄) | 번호 · 품명 및 규격 · 수량 · 단가(원) · 금액(원) | 예: `1 · AB-12-C-34 Motor … · 1 · 1,000,000 · 1,000,000` (가짜 값) | 품명 앞부분이 **모델/부품 코드**로 보임 (교체 부품 순위의 키). 빈 줄 많음 |
| 아래 왼쪽 표 | 납기 | `YYYY-MM-DD 수리완료` 처럼 날짜+글 | 날짜만 따로 뽑기 |
| 〃 | 결제 조건 | 예: "납품 완료 시 현금결제" | 미수금 연결 후보 (4장) |
| 〃 | 보증 기간 | 예: "보증 제외 품목" | 무상/유상 판단 근거 후보 |
| 〃 | 유효 기간 | 예: "견적 후 30일" | |
| 아래 오른쪽 표 | 총량 · 공급가액 · 부가세액 | 총량 = 수량 합으로 보임 | |
| 〃 | 담당자 | "이름 직급 / 휴대폰" | **직원 개인 연락처 — 이름만 저장, 전화번호는 저장하지 않는 쪽 추천** |
| 맨 아래 | 인증 문구 (벤처·이노비즈·ISO 등), 문서 코드 | 고정 | 읽지 않아도 됨. 문서 코드로 "견적서 양식인지" 판별 |

## 2. 금액 검증 규칙 (미리보기에서 경고, 오류면 저장 막기 — 2단계와 같은 정책)

1. 품목 줄마다 `수량 × 단가 = 금액`
2. `품목 금액 합 = 공급가액`
3. `부가세액 = 공급가액 × 10%` — **원 단위 처리(버림/반올림)는 고객사 확인 필요.** 확인 전에는 ±1원 차이는 경고만
4. `공급가액 + 부가세액 = 합계 금액(왼쪽 위 "부가세 포함" 금액)`
5. `총량 = 수량 합`
6. 금액 글자는 콤마·"원" 제거 후 정수(원)로. 음수·소수는 오류. 금액은 BigInt로 다룬다 (CLAUDE.md 코딩 규칙)
7. 견적 번호 형식이 다르거나 날짜와 YYMMDD가 다르면 경고 (오류는 아님)

## 3. 서비스팀 통계에 쓸 곳 (요구사항 `docs/02-team-requirements.md` 서비스팀)

| 서비스팀 요구 | 견적서에서 쓸 값 | 확인 필요 |
|---|---|---|
| 교체 부품 순위 | 품목 줄의 품명(앞부분 모델/부품 코드)별 수량·건수 | 품명 표기가 견적마다 같은지 (코드 표준화) |
| 교체 부품의 단가 / 단가 변동 | 같은 품명의 단가를 견적일 순으로 | 할인·특가가 단가에 섞이는지 |
| 출장 유상/무상 비율 | 견적서가 있으면 유상 후보 | **견적 ≠ 실제 수리**일 수 있음. 견적이 확정(수주)됐는지 표시하는 칸이 없음 → 고객사 확인 |
| 출장지 지역별 표시 (지도) | 사업명 앞부분의 지명 (예: "○○(정) …"에서 "○○") | 사업명 형식이 일정한지, 출장보고서의 지역과 어느 쪽을 기준으로 할지 (출장보고서 담당 팀은 고객사 질문 대기 — `docs/client-questions-2026-10-others.md` 서비스팀 1번) |
| A/S 제품 모델명 순위 | 품명의 모델 코드 | 부품 코드와 제품 모델 코드를 구분하는 규칙 |

## 4. 경영지원 쪽 연결 후보 (모두 고객사 확인 필요)

- **미수금 등록**: 결제 조건이 "납품 완료 시 현금결제"이면 납품(납기) 후 받을 돈이 생긴다. 견적서를 올리면 경영지원 미수금(또는 채권·채무 관리의 외상매출금)에 자동 등록할지 — **고객사 확인 필요**. 경영지원 쪽은 지금 미수금 관리와 채권·채무 관리를 합칠지 자체가 미정이다 (`docs/client-questions-2026-10.md` ①-1).
- **용역 매출**: 유상 A/S가 경영지원 월간 입력의 "용역 매출액"에 들어가는지 — 확인 필요.
- 연결한다면 **경영지원 모듈을 직접 import하지 말고** `modules/management/index.ts` 공개 함수로만 (CLAUDE.md "모듈 간 import 금지"). 필요한 함수가 없으면 경영지원 담당에게 요청.

## 5. 2단계 엑셀 이관에서 얻은 교훈 (참고)

| 교훈 | 2단계에서 생긴 일 | 견적서에 적용 |
|---|---|---|
| **"값 없음"과 "0"을 구분** | exceljs가 수식 계산값 0을 `cell.value`에서 빼서 "계산값 없음"으로 오인 → 불일치를 놓칠 뻔함 (PR #31) | 빈 품목 줄의 금액 칸(빈칸)과 0원을 구분. "0"이 찍힌 칸은 0, 칸에 글자가 없으면 없음 |
| **샘플 하나에 맞춘 가정이 깨짐** | 16행 샘플에선 그룹마다 2행 이상이라 "병합 = 그룹" 가정이 통했는데, 1행 그룹(병합 없음)에서 미분류로 나옴 (PR #32) | 품목 1줄 견적, 12줄 꽉 찬 견적, 비고·납기 빈 견적 등 **모양이 다른 가짜 견적서를 여러 장** 만들어 시험 |
| **위치를 고정하지 말 것** | 블록 시작 행을 행 번호가 아니라 제목 글자로 찾음 | 좌표를 고정값으로 쓰지 말고 라벨 글자("견적 번호", "공급가액")를 먼저 찾아 그 오른쪽/아래 값을 읽기 |
| **원본 서식의 의미는 고객에게 확인** | 빨간 글씨·연두 배경·날짜 서식·SUM 범위(자동이체 제외)의 의미를 추측하지 않고 질문으로 남김 | "보증 제외 품목", "(정)" 같은 표기의 의미는 추측하지 말고 고객사 질문으로 |
| **미리보기는 저장하지 않고, 저장 때 다시 읽기** | 미리보기 DB 쓰기 없음, 가져오기 때 파일 sha256·기존 행 수 확인 후 한 트랜잭션 | 같은 방식 추천. 같은 견적 번호를 두 번 올리면 막거나 덮어쓰기 확인 |
| **개인 정보는 처음부터 빼기** | AI 입력에서 거래처명 제외, 다운로드 로그에 비밀번호 등 미포함 | 담당자 휴대폰·수신자 이름은 저장 대상에서 빼는 쪽으로 설계 |
| **픽스처는 생성 스크립트로** | 원본 빈 양식 + 생성 스크립트로 픽스처를 다시 만들 수 있게 함 | PDF 생성 스크립트(가짜 내용)로 시험 파일을 만들어 커밋 |

참고 코드 (경영지원 모듈 — 복사해서 서비스 모듈에 맞게 쓰고, 직접 import는 하지 말 것):
- 엑셀 서식까지 읽기: `src/shared/upload/read-styled-sheet.ts` (공용)
- 해석·검증·미리보기·저장 계획 분리: `src/modules/management/ledger/import/` (`parse-ledger-sheet.ts` → `plan.ts` → `actions.ts` → `save-import.ts`)
- PDF는 CLAUDE.md 기술 스택대로 `pdfjs-dist`(글자 PDF), 스캔본은 Claude API — 단 위 0장의 동의 원칙

## 6. 고객사에 확인할 것 (서비스팀 정리본 후보)

1. 견적서가 확정(수주)됐는지 어떻게 알 수 있는지 — 견적서만으로 유상 A/S 건수로 셀지
2. 부가세 원 단위 처리 (버림/반올림)
3. 품명 표기 규칙 (모델·부품 코드가 항상 앞에 오는지)
4. 사업명의 지역 표기 규칙, 지도에는 견적서·출장보고서 중 어느 지역을 쓸지
5. 견적서 업로드 시 경영지원 미수금·용역 매출로 연결할지
6. 빈 견적서 양식(실데이터 없는 원본) 또는 이름을 가린 견적서 몇 장을 받을 수 있는지
